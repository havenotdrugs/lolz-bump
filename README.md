# lolz-bump

Telegram-бот, который по расписанию поднимает темы LOLZ. Бот заменяет прежний CLI и YAML-конфигурацию.

## Архитектура

- `app.py` собирает приложение и его внешние зависимости.
- `bot.py` принимает только личные сообщения администраторов, показывает один редактируемый экран с вложенными разделами и рассылает итоги окон.
- `scheduler.py` владеет планировщиком и не допускает одновременного выполнения окон.
- `service.py` выбирает темы и выполняет поднятия. Он не зависит от Telegram.
- `db.py` хранит настройки, историю, зашифрованный LOLZ-токен и ID экранов.
- `secrets.py` создаёт ключ в отдельном постоянном хранилище и шифрует токен перед записью в SQLite.

## Данные и правила

Настройки тем, домены их ссылок, персональные расписания и именованные шаблоны постинга создаются в SQLite через Telegram. При пустой базе задания не запускаются. Часовой пояс всегда `Europe/Moscow`. Для каждой темы хранится ID и домен `lolz.live` либо `zelenka.guru`; старые записи без домена автоматически получают `lolz.live` при чтении. Шаблон хранит только имя и список времён; его применение копирует расписание в тему и не создаёт постоянную связь.

В каждом окне поднимаются все активные темы: сначала важные, затем обычные. История попыток переживает перезапуск. Изменение расписания не меняет уже начатое окно, но применяется к следующим.

`LOLZ_API_TOKEN` вводится только через личный чат администратора. Бот удаляет введённое сообщение, шифрует токен и не записывает его в логи. Ключ шифрования не хранится в SQLite.

## Доступ

Единственная команда — `/start`. Главное меню содержит «Темы», «История» и «Системные настройки». В системных настройках доступны токен и управление шаблонами постинга: создание, переименование, изменение расписания и удаление. Доступ имеют только числовые Telegram ID из `TELEGRAM_ADMIN_IDS`. Бот игнорирует остальных пользователей и групповые чаты.

## Конфигурация запуска

- `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.
- `TELEGRAM_ADMIN_IDS` — ID администраторов через запятую.
- `STATE_DB_PATH` — необязательный путь к SQLite; по умолчанию `state.db`. В Docker Compose путь фиксирован как `/data/state.db`, а база хранится в `./data/state.db`.
